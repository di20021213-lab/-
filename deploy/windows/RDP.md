# Удалённый рабочий стол Windows через свой сервер

Мини-ПК за CGNAT: своего адреса в интернете у него нет, и напрямую к нему не
подключиться. Поэтому экран идёт по тому же SSH-туннелю до зарубежного сервера,
который уже поднят ради Telegram. Наружу при этом **ничего не открывается** —
порт виден только внутри туннеля.

```
телефон ──SSH──> сервер 87.58.205.159 <──SSH── мини-ПК
         (-L 3389)                    (-R 3389)
```

## 1. Включить RDP на мини-ПК

PowerShell **от администратора**:

```powershell
Set-ItemProperty -Path 'HKLM:\System\CurrentControlSet\Control\Terminal Server' -Name fDenyTSConnections -Value 0
```

```powershell
Enable-NetFirewallRule -DisplayGroup "Remote Desktop"
```

Проверить, что слушает:

```powershell
Get-NetTCPConnection -LocalPort 3389 -State Listen
```

Должна появиться строка. Пусто — значит служба не поднялась, смотри «Если не
работает» внизу.

## 2. Пароль у учётной записи — обязателен

**RDP не пускает учётки без пароля.** Если ставил Windows без пароля, задай:

```powershell
net user %USERNAME% *
```

Пароль вводится вслепую, символы не показываются — это нормально.

Он же будет единственной защитой твоего рабочего стола, так что длинный и
не такой, как где-то ещё.

## 3. Добавить проброс экрана в туннель

Открой `deploy\windows\tunnel.bat` и допиши в команду `ssh` строку:

```
    -R 127.0.0.1:3389:127.0.0.1:3389 ^
```

Должно получиться примерно так:

```
ssh -N -D 127.0.0.1:1080 ^
    -R 127.0.0.1:3389:127.0.0.1:3389 ^
    -o ServerAliveInterval=30 -o ServerAliveCountMax=3 ^
    ...
```

`127.0.0.1:` в начале — не для красоты: без него порт повис бы на внешнем
адресе сервера, и твой рабочий стол увидел бы весь интернет.

Перезапусти `tunnel.bat`. Проверить с сервера, что порт появился:

```powershell
ssh root@87.58.205.159 "ss -tlnp | grep 3389"
```

## 4. Подключиться с телефона

**Шаг 1 — проброс.** В Termius (или любом SSH-клиенте) создай подключение к
`root@87.58.205.159` и добавь локальный проброс:

| Поле | Значение |
|---|---|
| Local port | 3389 |
| Destination host | 127.0.0.1 |
| Destination port | 3389 |

Подключись — окно оставь открытым.

**Шаг 2 — RDP.** Поставь клиент Microsoft (в магазине он называется
**Windows App**, раньше был Microsoft Remote Desktop). Добавь ПК:

| Поле | Значение |
|---|---|
| Адрес | `127.0.0.1:3389` |
| Пользователь | твоя учётка Windows |
| Пароль | из пункта 2 |

## Если не работает

| Симптом | Причина |
|---|---|
| `Get-NetTCPConnection` ничего не вернул | Служба RDP не запущена: `Start-Service TermService` |
| Клиент пишет «учётные данные не работают» | У учётки нет пароля (пункт 2) либо не тот логин. Логин смотри: `whoami` |
| Подключение сразу рвётся | Не поднят туннель на мини-ПК или не сделан проброс на телефоне |
| На сервере порт 3389 занят | Смени номер: в обоих местах пиши, например, 13389 |
| Заходит, но экран чёрный | Подожди — первый вход создаёт профиль, это долго |

## Про безопасность

Порт 3389 **не открыт в интернет**: и на сервере, и на мини-ПК он привязан к
`127.0.0.1`, попасть на него можно только через SSH-туннель. Не убирай
`127.0.0.1:` из проброса и не открывай 3389 на роутере — RDP, доступный
снаружи, ломают перебором пароля так же, как и всё остальное.
