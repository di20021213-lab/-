# Экран мини-ПК на телефоне: решить капчу руками

## Сначала — чего это не лечит

Авито заворачивает нас двумя разными способами, и лечатся они по-разному.

| Что на снимке | Что это | Что делать |
|---|---|---|
| «Доступ ограничен», «проблема с IP», HTTP 429 | Лимит по адресу | Нажимать нечего. Снимается только временем без запросов. Бот уже сам уходит в паузу |
| Кнопка «Продолжить», пазл, «подтвердите, что запросы отправляли вы» | Капча | Вот её и решаем этим экраном |

Бот присылает снимок страницы блокировки в Telegram — посмотри, что там было
в последний раз. А сколько чего прилетало за три дня, считает эта команда
(она читает только журнал, к Авито не ходит и бюджет адреса не тратит):

```bash
journalctl -u avito-watcher --since "3 days ago" --no-pager \
  | grep -o "антибот/капчу Авито (HTTP [0-9]*)" | sort | uniq -c
```

`HTTP 429` — лимит, экран не поможет. `HTTP 200` — страница-заглушка, которую
в принципе можно пройти руками.

**И главное: экран не увеличивает лимит адреса.** Как ходили раз в 20–30 минут,
так и будем. Он нужен для другого: когда капча всё-таки вылезла, а ты не дома,
бот стоит до твоего возвращения. С экраном — не стоит.

## Почему не голый SSH

На мини-ПК стоит Ubuntu Server — графики там нет вообще, ни одного окна. SSH
передаёт текст: в терминале капчу не показать и пальцем в неё не ткнуть.
«Виртуальная мышь» в Termius двигает текстовый курсор в терминале, а не
указатель по странице.

Поэтому схема такая: на мини-ПК поднимается виртуальный экран (Xvfb), к нему
цепляется VNC, и в нём открывается **тот же самый Chromium с тем же профилем**,
которым ходит бот. Решённая капча ложится в общий профиль — бот подхватит её
на следующем цикле. Профиль общий, браузер тот же: Авито не увидит, что
устройство сменилось.

## Поставить (один раз)

```bash
sudo apt install -y xvfb x11vnc
```

Около 40 МБ на диске. В памяти — ноль: всё поднимается только на время сеанса
и гасится на выходе.

## Запустить

На мини-ПК:

```bash
cd ~/avito-watcher && ./deploy/minipc/screen.sh
```

Первый запуск попросит придумать пароль для VNC — он сохранится в `~/.vnc/passwd`.

Скрипт сам:
1. ставит флаг паузы, чтобы бот не полез в тот же профиль (один профиль двумя
   Chromium не открыть — полезет, уронит тебе окно посреди капчи);
2. ждёт, пока бот закроет свой браузер (обычно секунды: он открыт около минуты
   из каждых двадцати);
3. поднимает экран, VNC и браузер на нужной странице;
4. на выходе всё гасит и снимает паузу.

## С телефона

**1. Проброс порта.** Termius → хост мини-ПК → Port Forwarding → Local:

```
Local port   5900
Host         127.0.0.1
Remote port  5900
```

Подключись, чтобы проброс поднялся.

**2. Смотреть.** bVNC или RealVNC Viewer → `127.0.0.1:5900` → пароль от VNC.

Дальше — обычный браузер под пальцем. Решил капчу, закрыл окно — сеанс
закончился сам.

## Про безопасность

Порт VNC слушает **только localhost** (`-localhost` у x11vnc). Наружу он не
выставлен: с телефона мы заходим через тот же SSH-туннель до зарубежной VDS,
который уже есть. Изоляция мини-ПК от роутера не трогается — новых дырок в
сети не появляется.

Пароль на VNC обязателен даже на localhost: без него любой процесс на машине
получает твой экран и профиль с куками одной командой.

## Если что-то пошло не так

**Бот молчит, а сеанс давно закончен.** Проверь флаг: `ls ~/avito-watcher/PAUSE.flag`.
Если он есть — удали. Но специально следить не надо: флаг протухает через час
сам, и бот возвращается к работе без перезапуска.

**«бот держит профиль больше 4 минут».** Он застрял в длинном цикле. Останови
его на время сеанса: `sudo systemctl stop avito-watcher`, а после —
`sudo systemctl start avito-watcher`.

**Чёрный экран в VNC.** Браузер ещё не нарисовался, дай 5–10 секунд. Если
так и осталось — посмотри, что пишет скрипт в терминале.
