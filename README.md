# Колхоз «Червонэ дышло»

Браузерная ферма в духе соцсетевых игр начала 2010-х: аккаунты по почте, база SQL,
серверная экономика. Собрана по скриншотам оригинала — сезоны, серебро и кристаллы,
энергия, задания, магазин с боковым меню и страницами, ежедневный подарок.

## Запуск

```bash
npm install
npm run migrate        # создаёт var/kolhoz.db по server/db/schema.sql
npm start              # http://localhost:3000
```

SMTP настраивать не обязательно: без него письмо с ссылкой подтверждения
складывается в `var/mail/*.eml`, а сама ссылка печатается в консоль сервера.
Боевые настройки — в `.env.example`.

```bash
npm run smoke          # сквозная проверка: регистрация → письмо → игра → база
```

Настройки читаются из `.env` в корне проекта, если он есть; переменные окружения
имеют приоритет над ним.

## Запуск на Windows

Собирать нечего — сборки у проекта нет, есть Node.js и папка с файлами.
Клиент отдельно раздавать тоже не нужно: страницу выдаёт сам сервер,
игроку достаточно ссылки и браузера.

1. Поставьте **Node.js LTS, 64-бит** с [nodejs.org](https://nodejs.org) — установка обычная.
2. Скачайте проект: `git clone` или кнопка **Code → Download ZIP** на GitHub и распаковать.
3. Двойной клик по `windows\1-install.bat` — поставит зависимости, создаст базу и `.env`.
4. Двойной клик по `windows\2-start-server.bat` — сервер запущен.
   В окне будут адреса: `http://localhost:3000` для вас и `http://192.168.х.х:3000` для остальных.
   Пока окно открыто — сервер работает; закрыли окно — выключили.
5. Чтобы игроков пустило из вашей сети, один раз запустите
   `windows\3-open-firewall.bat` **от имени администратора** — правой кнопкой по файлу.
6. `windows\4-make-player-link.bat` сделает файл `Kolhoz.url` с адресом сервера —
   вот его и рассылайте. Или просто отправьте ссылку текстом.

Windows может показать синее окно SmartScreen на .bat из интернета —
«Подробнее» → «Выполнить в любом случае». Файлы открываются блокнотом, там четыре строки.

### Что поправить в .env перед раздачей

- `PUBLIC_URL` должен совпадать с адресом, по которому заходят игроки
  (`http://192.168.1.50:3000`), иначе ссылки в письмах приведут их на собственный localhost.
- Почта. Либо настоящий SMTP — `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`
  (у Яндекса и Gmail нужен пароль приложения, не основной пароль от ящика),
  либо, если играете в своей сети и почтовика нет, `REQUIRE_EMAIL_VERIFY=false` —
  тогда после регистрации пускает сразу. Пароли при этом всё так же хешируются,
  но чужой почтой сможет назваться кто угодно, так что в интернет с этим не выходите.
- `PORT` — если 3000 занят.

### Играть не только по локальной сети

- **Проброс порта.** На роутере пробросить внешний порт на этот компьютер и
  прописать `PUBLIC_URL=http://ваш-внешний-адрес:порт`. Нужен белый IP.
- **Туннель.** Cloudflare Tunnel или ngrok — дают внешний https-адрес без настройки роутера.
  Этот адрес и пропишите в `PUBLIC_URL`: на https кука сессии автоматически станет `Secure`.

### Мелочи эксплуатации

- Вся база — один файл `var\kolhoz.db`. Резервная копия это копия файла;
  лучше при остановленном сервере.
- Автозапуск при загрузке — Планировщик задач Windows или nssm.
- Одним `.exe` это не упаковать: `better-sqlite3` — нативный модуль, в SEA и pkg
  он нормально не заворачивается. Node плюс батник честнее и чинится без меня.

### Если не заработало

| Что видно | В чём дело |
|---|---|
| `node не является внутренней или внешней командой` | Node не установлен или окно cmd открыто со старым PATH — переоткройте |
| `npm install` падает на `better-sqlite3` | Не LTS или 32-бит: под них нет готовой сборки. Поставьте Node.js LTS x64 |
| `Порт 3000 уже занят` | Второй сервер запущен или порт занят другой программой — смените `PORT` в `.env` |
| Игроки не открывают страницу | Брандмауэр (пункт 5), сеть помечена как «Общедоступная», или вы в разных сетях |
| Письма не приходят | SMTP не настроен — письмо лежит в `var\mail\*.eml`, ссылка напечатана в окне сервера |
| Кракозябры в окне сервера | Кодировка консоли, на работу не влияет |

## Что где

```
public/          клиент: разметка, стили, справочник, игровой скрипт
  content.js     породы, корма, постройки, задания — общий файл для клиента и сервера
server/db/       schema.sql — вся схема базы
server/src/      db, auth, mail, game (правила), index (маршруты)
server/test/     сквозной тест
offline/         ранняя версия одним файлом, без сервера, хранит прогресс в localStorage
```

## Аккаунты

Регистрация по почте с подтверждением: без перехода по ссылке из письма играть нельзя
(`/api/game` отвечает `403 email_unverified`). Есть вход, выход, сброс пароля по ссылке.

- Пароли — `scrypt` из стандартной библиотеки Node, соль на каждого пользователя,
  сравнение через `timingSafeEqual`. Открытым текстом пароль нигде не лежит.
- В базе от токенов (подтверждение почты, сброс пароля, сессия) хранится только SHA-256.
  Сам токен уходит в письмо или в куку и больше нигде не появляется.
- Сессия — кука `HttpOnly; SameSite=Lax` (и `Secure`, если `PUBLIC_URL` на https).
  Сессии живут в базе, поэтому их можно погасить с сервера.
- Регистрация не говорит, занят ли адрес: на занятый неподтверждённый просто уходит
  письмо заново. Вход, отправка писем и сброс пароля ограничены по частоте.

## Экономика считается на сервере

Клиент отправляет намерение (`посадить`, `покормить`, `собрать`, `сдать`, `улучшить`),
сервер берёт цены и сроки из `public/content.js`, проверяет и возвращает новое состояние.
Цену, урожай или количество из запроса он не читает — в тесте это проверяется отдельно.
Каждое действие пишется в таблицу `events`.

## Схема базы

`users` · `email_tokens` · `sessions` · `rate_limits` — аккаунты и доступ.
`farms` · `buildings` · `slots` · `inventory` · `products` · `decor` · `helpers` ·
`counters` · `friend_help` · `events` — хозяйство. Плюс вид `leaderboard` для TOP 100.

Диалект SQLite; перенос на PostgreSQL описан комментарием в начале `server/db/schema.sql`.

## API

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/auth/register` | завести аккаунт, отправить письмо |
| GET | `/api/auth/verify?token=` | подтвердить почту и сразу войти |
| POST | `/api/auth/resend` | выслать письмо заново |
| POST | `/api/auth/login` `/logout` | вход и выход |
| GET | `/api/auth/me` | кто вошёл |
| POST | `/api/auth/forgot` `/reset` | сброс пароля по ссылке |
| GET | `/api/game` | текущее состояние хозяйства |
| POST | `/api/game/:action` | `plant`, `feed`, `feedAll`, `harvest`, `harvestAll`, `sell`, `sellAll`, `upgrade`, `buy`, `useItem`, `feedPet`, `daily`, `helpFriend`, `gift`, `rename` |
| GET | `/api/top` | таблица рекордов |
| GET | `/api/content` | справочник пород, кормов и построек |

## Правила игры

1. Купи живность или рассаду — она занимает место в постройке.
2. Покорми (полей) — начинается созревание.
3. Собери урожай. Каждый сбор тратит один **сезон**; когда сезоны кончились,
   подопечный уходит со двора.
4. Сдай продукцию на складе.

- **Сезоны.** У породы указано `Сезон: 3` — столько урожаев она даст. «Чистая прибыль»
  в карточке считается как `урожайность × цена единицы × сезоны − цена`.
  Для «Русской белой»: 47 × 3 × 3 − 150 = 273.
- **Время.** Одна реальная секунда = 4 игровые минуты, поэтому «созревание 4 ч. 00 мин.»
  проходит за минуту. Сроки показаны в игровом времени, как в оригинале.
- **Корма.** Сорт ускоряет созревание и повышает урожайность: низкий — полный срок,
  элитный — четверть срока и +50% урожая.
- **Питомцы.** Сытый пёс даёт +3% к урожайности двора, кот +5%. Сытость падает со временем.
- **Декор** прибавляет проценты урожайности, **улучшения** увеличивают число мест
  (3 → 5 → 8 → 12) и требуют досок из раздела «Ресурсы».
- **Помощники** работают сами: батрак собирает готовое, пастушок кормит голодных.
- **Энергия** тратится по единице на действие и восстанавливается по единице в 15 секунд.

## Что взято из оригинала, а что придумано

Из скриншотов: «Русская белая» со всеми цифрами, сорта кормов, разделы и подразделы
магазина, подарки (вилы, поилка, кормушка, почётная грамота), формулировки заданий,
вкладки нижней панели, модалка «Задание выполнено», бейдж «осталось N».

Придумано: остальные породы и растения, цены улучшений, помощники, бонусы, соседи.
Графика своя — оригинальные спрайты не воспроизводятся.
